# 管理员功能实现与本地核验

本文保留管理员阶段的验证记录；最新整体结果见 [整体联调与程序验收](acceptance.md)。

本文件说明程序实现与开发验证，不是实验报告。规则沿用实验一 REQ-011、REQ-014、REQ-015，
以及实验二 UML 中 ProductService、ReservationService.cancelForBlocking、StatisticsService、
LogService 和管理员商品、统计与日志原型。测试账号和商品均为生成的隔离数据。

## 入口与权限

- `/admin`：管理员工作台。
- `/admin/products`：默认待审核，选择全部或其他状态可进入相应商品详情处理违规。
- `POST /products/<id>/actions/block`：屏蔽，原因必填，最多 1000 字。
- `POST /products/<id>/actions/restore`：仅把已屏蔽商品恢复为草稿。
- `/admin/statistics`：交易统计及本次计入记录。
- `/admin/logs`、`/admin/logs/<id>`：日志组合查询及完整详情。

首个与后续管理员均可执行上述业务管理；普通用户拒绝，游客要求登录。
屏蔽、恢复必须 POST、有效 CSRF 和页面原商品版本；不能伪造 actor 或角色来改变操作人。
所有数据访问范围在服务端检查。卖家和买家通过自己的商品/预约历史看到屏蔽及取消原因。

## 屏蔽、联动取消与恢复

可以屏蔽草稿、待审核、已发布、已预约、已确认和已下架商品。已完成交易不可改写，
已屏蔽商品不接受再次屏蔽。原因经去除首尾空白后保存，HTML 展示转义。

1. 独立数据库事务的第一条 SQL 为商品状态和版本的条件更新，不先建立过期的读取快照。
2. 有有效预约时，检查商品与预约状态匹配，预约转为已取消，记录管理员、原因及取消时间；
   商品最终为已屏蔽，不能像普通取消那样释放为已发布。
3. 同一事务递增商品及联动预约版本、保存最近屏蔽原因，写入一条 BLOCK_PRODUCT 复合事件。
   日志同时保存商品、预约的编号和前后状态；不伪造普通用户取消请求记录。
4. 任一写入或提交中断，商品、预约、原因、版本及日志全部回滚。

预约唯一有效约束仍由数据库保证，没有进程内业务互斥锁。屏蔽与预约、确认、取消、完成竞争时，
同一页面版本最多一个成功，失败方为 409；不会用旧页面跨状态覆盖成功结果。
同一版本重复屏蔽或恢复仅一次成功、一次日志，其余明确冲突。

恢复只允许 BLOCKED → DRAFT，增加商品版本并记录 RESTORE_TO_DRAFT；旧预约保持取消，
必须由卖家重新提交并经管理员审核才能发布。旧成功请求重放只返回原预约当前状态，
不会复活旧预约，也不会影响恢复、重新审核后建立的新预约。
若发现商品与有效预约状态不匹配，则拒绝操作并回滚，不隐式修复历史数据。

## 交易统计口径

默认查询当前北京时间月份，也可输入起止日期，包含首尾两天。
后端把北京时间区间转换为 UTC 的半开区间再查询，包含结束日最后一秒的微秒部分，
排除下一天零点。无效/反向日期、溢出或非法页码返回 400，保留输入，不展示替代区间的统计。

只汇总状态为 COMPLETED 的预约，以首次 completed_at 归属日期，每条预约只计一次。
数量与预约 reserved_price_cents 在 SQL 聚合；合计以整数分累加、Decimal 格式化，
不用商品现价、浮点累计或实际收款数据。无记录时显示 0 笔和 ¥0.00。

计入明细每页 20 条，按首次完成时间、编号倒序；总数与合计覆盖完整区间，不随分页缩小。
汇总与明细从同一个读取事务快照取得，不单独保存统计总表。

## 操作日志

筛选条件可任意组合：开始/结束北京时间、操作人用户名或编号（精确匹配）、商品编号、
预约编号、操作类型。时间精确到秒，包含所填首尾秒；单端或双端留空均可。
所有非空条件须同时匹配；时间、类型、对象编号与页码无效时返回 400，保留输入。

按操作时间、编号倒序，每页 20 条。详情展示操作人、时间、商品及可选预约、两类前后状态、
完整适用原因。后续状态变化不覆盖旧日志。不查询或输出密码哈希、成功请求标识、会话令牌。
仅提供 GET 查询，没有日志编辑、删除 API；失败或冲突操作不生成成功日志。

## 已有数据库升级

停止服务后先备份 SQLite，再执行 `flask --app app init-db`。
初始化兼容本项目的商品阶段日志表和预约阶段日志表，扩展日志类型 CHECK，并保留全部已有字段。
复制、核对数量、替换表及重建索引在同一事务中完成。自定义索引、触发器或未知结构拒绝猜测改写。
迁移测试包含有实际商品及预约日志的数据与替换表中断回滚；初始化可重复执行。

本机升级前备份位于 `instance/backups/before-admin-20261031-181534.sqlite3`。
本机当时六张业务/会话表均为空；已逐表核对升级前后内容及外键。
`instance/admin-schema-check.json` 保存本机核对结果，测试生成数据没有写入日常数据库。
