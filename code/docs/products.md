# 商品管理实现说明

本模块承接实验二的 Product、ProductService、ProductCategory、ProductStatus 设计。
本阶段实现 REQ-003、REQ-004、REQ-005、REQ-006，以及相关权限、持久化、日志和查询性能约束。

## 状态与操作

| 当前状态 | 操作 | 身份 | 成功后 |
|---|---|---|---|
| 草稿 | 保存 | 所属卖家 | 草稿，版本递增 |
| 草稿 | 提交审核 | 所属卖家 | 待审核 |
| 待审核 | 撤回 | 所属卖家 | 草稿 |
| 待审核 | 审核通过 | 管理员 | 已发布，保存最近发布时间 |
| 待审核 | 驳回并填写原因 | 管理员 | 草稿，保存最近驳回原因 |
| 已发布 | 下架 | 所属卖家 | 已下架 |
| 已发布或已下架 | 退回草稿 | 所属卖家 | 草稿，修改后仍需审核 |

创建时可以“保存草稿”或“提交审核”。后者在同一个数据库事务中创建完整商品并记录提交日志。
修改草稿时的“保存并提交”也只提交一次事务，不会先保存错误数据再报告提交失败。
不提供直接改价、直接重新上架、删除商品或批量库存管理。

已预约、已确认、已完成、已屏蔽状态已在枚举中保留，卖家不能通过本模块直接编辑、下架或重发。
预约交易现已接入，详见 reservations.md；违规屏蔽/恢复见 admin.md。

## 权限和入口

- `/products`：游客也可浏览，固定只查询已发布商品。首页使用同一商品大厅。
- `/my/products`：普通账号按状态查询自己的商品。
- `/products/new`、`/products/<id>/edit`：普通账号创建或编辑自己的草稿。
- `/admin/products`：两种管理员均可审核和查询全部商品，默认显示待审核；选择全部状态可查看其他状态。
- `/products/<id>`：公开商品可匿名查看，非公开商品仅所属卖家和管理员可查看。
- `/products/<id>/image`：应用相同的详情可见性规则，图片不直接存入 static 目录。

私有商品对无关账号返回 404，不泄露其名称、描述或图片。受限卖家操作和审核操作均在服务端检查身份。
卖家编号、初始状态、版本、发布时间由服务端设置；表单中的 seller_id、actor、status 等额外字段无授权作用。
图片、详情和动态页面使用 no-store，避免下架后从浏览器缓存继续读取非公开内容。

## 输入与图片

草稿可缺名称、分类、价格和描述；但已填写的字段必须有效。提交审核时四项均必填。
名称最多 100 字符、描述最多 5000 字符，固定五类，不新增联系方式或成色字段。
联系方式与线下交付说明写入描述并按文本展示，系统不自动识别或核实其内容。
价格大于 0、最多两位小数，上限 99999999.99 元；数据库按整数“分”保存，实体 price 属性返回 Decimal。
驳回原因必填，最多 1000 字符。表单错误保留其他文本输入，旧版本错误保留原版本而不自动重试覆盖。

商品最多一张可选 JPG、PNG 或 WebP 图片，最多 3 MB、1600 万像素，拒绝动画和非图片内容。
Pillow 验证实际文件内容，存储名称由服务端随机生成；不使用浏览器提交的文件路径。
图片先成功写入，再提交数据库；数据库失败则清理新文件。替换成功后才清理旧文件。
所有者变更失败不会留下新文件或修改原有文件；重启后图片和商品关联仍可读取。
文件选择控件因浏览器限制在错误返回后需重新选择，页面已提示。

## 事务和查询

ProductService 的草稿创建/更新、transition、search、get_detail 分别对应 UML 中相应操作。
transition 使用明确的操作表映射 submitForReview、withdrawReview、approve、reject、takeDown、returnToDraft。

状态操作的第一条 SQL 按“编号 + 当前版本 + 允许状态 + 适用所有者”条件更新版本，并取得待更新记录。
因此没有先读取旧数据再无条件写入的窗口；SQLite 同时写请求串行等待，旧状态或旧版本返回 409。
商品字段/状态、版本、关键 OperationLog 在同一事务提交，日志失败也会回滚状态和版本。
日志记录提交、撤回、通过、驳回、下架、退回草稿；不提供日志修改/删除接口；管理员只读日志查询界面见 admin.md。

组合查询在数据库执行名称关键词、固定分类、含端点价格范围和适用状态过滤。
% 和 _ 按普通关键词字符匹配，不作为通配符扩展；使用绑定参数。
公开列表按最近发布时间、编号倒序稳定排序，每页 12 条；个人和管理员列表按创建时间、编号倒序。
列表一次联表读取所需卖家名称，不逐件单独查询；不读取卖家密码哈希用于展示。
为公开状态/发布时间、分类和所属卖家/状态创建索引。

## 本地初始化与验证

已有用户版本升级至本轮，只需在 code 目录重新执行 init-db 创建新增表；它不删除用户和会话。
init-db 除创建缺失表外，已支持预约模块所需的已知旧日志表事务升级；不承担任意自定义结构迁移。

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.lock.txt
.\.venv\Scripts\python.exe -m flask --app app init-db
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m pylint app tests tools
.\.venv\Scripts\python.exe -m tools.verify_product_queries
```

自动化测试使用独立 SQLite 和图片目录，覆盖流程、错误保留、权限矩阵、并发状态冲突、
日志故障回滚、上传校验、图片替换/清理、重启、组合过滤和稳定分页。
性能工具生成 1000 条隔离商品数据，使用 10 个并发客户端执行共 100 次真实 HTTP 请求。
全部请求都保留在结果中；成功、预期列表内容正确且不超过 2 秒，才算达标，至少需要 95 次。
测量包括 HTTP、SQL 和 HTML 渲染，不包含图片文件下载，不代表跨机器或生产环境性能。
实际结果保存到 instance/product-query-check.json，测试数据库结束后清理。
